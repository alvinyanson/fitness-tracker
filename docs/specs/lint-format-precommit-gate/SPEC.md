# Feature: oxlint + Prettier + Husky pre-commit gate

> Source: [GitHub issue #2](https://github.com/alvinyanson/fitness-tracker/issues/2) —
> `chore: oxlint + prettier + husky + lint-staged pre-commit gate` · Milestone
> **M1 — Core BLE + local tracking**

## Intent

Every commit is automatically linted and formatted before it lands: `oxlint` catches
correctness problems, Prettier normalizes style, and a Husky `pre-commit` hook runs both
through `lint-staged` against only the staged files — so style drift never has to be
retrofitted once more screens and services exist.

## Context

- **Problem statement:** No lint, format, or git-hook tooling exists in the repository
  today. `package.json` (`package.json:19-22`) declares exactly two `devDependencies` —
  `@types/react` and `typescript` — and no `scripts` entry beyond `start`/`android`/`ios`/
  `web`. There is no `.oxlintrc.json`, `.prettierrc`, `.husky/`, or `lint-staged` config
  anywhere in the tree, and `.git/config` has no `core.hooksPath` set. `CLAUDE.md` already
  lists `oxlint`, `prettier`, `husky`, `lint-staged` as Milestone 1 stack items (§ Tech
  stack) — this issue is what actually installs and wires them.
- **Current code:** Seven source files exist under `src/` (`src/app/{_layout,index,
workout,history,summary/[id]}.tsx`, `src/theme/{colors,typography,layout,index}.ts`) —
  see `docs/specs/expo-router-src-scaffold/SPEC.md`. They already follow a consistent
  hand-written style (2-space indent, single quotes, semicolons, trailing commas on
  multiline literals — verified in `src/app/_layout.tsx` and `src/app/index.tsx`), which
  this issue turns into an enforced, tool-checked convention rather than an implicit one.
- **User impact:** No end-user-facing change. For maintainers: `git commit` now
  auto-fixes formatting on staged files and blocks a commit that contains a real lint
  error; `pnpm lint` and `pnpm format` become the manual entry points.
- **Dependencies:** None of Milestone 1's other open issues (BLE pairing, session
  recording, storage) depend on this one, but every future commit passes through the gate
  this issue adds, so it is worth landing before the file count grows. No conflicting
  devDependency exists today — the issue's note "do not add ESLint alongside oxlint" is
  satisfied by construction, since ESLint is not currently installed.

## Interfaces / API

### `oxlint` (`.oxlintrc.json`)

Generated via `pnpm dlx oxlint --init` and then edited. Oxlint's `eslint`, `typescript`,
`unicorn`, and `oxc` rule plugins are enabled by default; `react` is not and must be added
explicitly, or specifying `plugins` at all overwrites that default set
(https://oxc.rs/docs/guide/usage/linter/config.html). Final shape:

```jsonc
{
  "plugins": ["eslint", "typescript", "unicorn", "oxc", "react"],
  "ignorePatterns": [
    "android/**",
    ".expo/**",
    "dist/**",
    "web-build/**",
    "node_modules/**",
  ],
}
```

`ignorePatterns` lives in the config file rather than a separate `.oxlintignore`, per
oxlint's own recommendation, so every tool and editor integration shares one ignore list
(https://oxc.rs/docs/guide/usage/linter/ignore-files.html). `android/` is generated by
`expo prebuild` and already git-ignored (`.gitignore:41`) but is present on disk locally,
so it must still be excluded from lint runs.

No `typescript.typeAware` option is enabled — see Constraints.

### Prettier (`.prettierrc.json`, `.prettierignore`)

```json
{
  "tabWidth": 2,
  "singleQuote": true,
  "semi": true
}
```

These three keys are the only ones the issue calls out ("tab width / quotes /
semicolons") and are chosen to match the style already present in `src/`, not invented.
Every other Prettier option (e.g. `trailingComma: "all"`, `printWidth: 80`) stays at its
v3 default rather than being pinned here, since the existing code already conforms to
those defaults and the issue doesn't ask for them to be settled.

`.prettierignore`:

```
android/
.expo/
dist/
web-build/
pnpm-lock.yaml
```

### `package.json` scripts

| Script        | Command              | Contract                                                                       |
| ------------- | -------------------- | ------------------------------------------------------------------------------ |
| `pnpm lint`   | `oxlint .`           | Exits non-zero if any `error`-severity rule fires. Read-only, no autofix.      |
| `pnpm format` | `prettier --write .` | Rewrites every file Prettier covers in place; exits 0 regardless of diff size. |

### `lint-staged` (`package.json` → `"lint-staged"` key)

```json
{
  "*.{ts,tsx,js}": ["oxlint --fix", "prettier --write"],
  "*.{json,md}": "prettier --write"
}
```

**Deviation from the issue's literal wording, flagged:** the issue's checklist glob is a
single `*.{ts,tsx,js,json,md}` pattern for "oxlint --fix + prettier". Oxlint lints
JavaScript/TypeScript syntax; running it against `.json` or `.md` files is a no-op at
best and an error at worst, so the two tools are split by pattern. Prettier still runs
across the full extension set from the issue, satisfying the intent (staged config and
doc files get formatted too) without asking oxlint to parse non-code files.

`oxlint --fix` applies its available auto-fixers before Prettier reformats the result
(https://oxc.rs/docs/guide/usage/linter/automatic-fixes.html). If `oxlint --fix` leaves a
real error behind, it exits non-zero, `lint-staged` aborts before the `prettier --write`
step, and Husky blocks the commit.

### Husky (`.husky/pre-commit`)

v9 setup — no more `.husky/husky.sh` boilerplate. `package.json` gets a `"prepare":
"husky"` script (so `pnpm install` re-creates the hook after a fresh clone); `.husky/`
holds one file:

```sh
pnpm exec lint-staged
```

`husky init` (or the manual steps above) also sets `core.hooksPath` to `.husky` in local
git config — this is host-repo config, not a tracked file, so every clone must run `pnpm
install` once (which the `prepare` script does automatically) before the hook is live.

## Implementation Steps

1. **Install.** `pnpm add -D oxlint prettier husky lint-staged`. Plain `pnpm add`, not
   `npx expo install` — none of these four are Expo-managed packages.
2. **oxlint config.** Run `pnpm dlx oxlint --init` to scaffold `.oxlintrc.json`, then edit
   it to the `plugins`/`ignorePatterns` shape above.
3. **Prettier config.** Create `.prettierrc.json` and `.prettierignore` per Interfaces /
   API.
4. **Scripts.** Add `"lint": "oxlint ."` and `"format": "prettier --write ."` to
   `package.json` `scripts`.
5. **Husky.** Add `"prepare": "husky"` to `scripts`, run `pnpm run prepare` once to create
   `.husky/` and set `core.hooksPath`, then replace the generated `.husky/pre-commit`
   contents with `pnpm exec lint-staged`.
6. **lint-staged config.** Add the `"lint-staged"` block to `package.json` per Interfaces
   / API.
7. **Baseline pass.** Run `pnpm format` once against the existing seven `src/` files plus
   root config files, so the tree starts from a fully-formatted baseline rather than
   surfacing pre-existing drift on someone else's next commit.
8. **Verify `pnpm lint` is clean.** Run `pnpm lint` against the current `src/` tree (the
   acceptance criterion). Fix anything oxlint's default `error`-severity rules flag; do
   not suppress a rule just to pass — if a real finding shows up, fix the underlying code.
9. **Manual hook test (auto-fix path).** Stage a file with deliberately wrong formatting
   (e.g. double quotes, tabs) or add a bug and revert it before committing anything with
   sensitive content, run `git commit`, and confirm the file is rewritten in place and the
   commit succeeds.
10. **Manual hook test (rejection path).** Stage a file containing a real lint error (e.g.
    an unreachable `return`, an unused variable oxlint's default rules flag as an error),
    attempt `git commit`, and confirm the hook exits non-zero and the commit is refused.
    Revert the deliberate error before landing this change.

## Style & Conventions

- `CLAUDE.md` § Tech stack, Milestone 1: names `oxlint`, `prettier`, `husky`,
  `lint-staged` as in-scope now — this issue is that install, in order.
- Issue note: "do not add ESLint alongside oxlint" — no `eslint` package, no
  `.eslintrc*` file, is added by this change. Oxlint's bundled `eslint` _plugin_ (core
  rules re-implemented in Rust) is unrelated to the ESLint _tool_ and is not a violation
  of this constraint.
- Prettier's three pinned keys match the style already present in `src/app/` and
  `src/theme/` (verified by reading `src/app/_layout.tsx` and `src/app/index.tsx`) rather
  than being chosen arbitrarily.
- Install with `pnpm`, per `CLAUDE.md` § Non-negotiables — none of these four packages
  are Expo SDK-managed, so plain `pnpm add -D` is correct (not `npx expo install`).

## Acceptance Criteria

- [ ] `pnpm lint` (`oxlint .`) exits 0 against the current `src/` tree.
- [ ] A commit containing a deliberately mis-formatted staged file is rewritten to
      conform to `.prettierrc.json` by the pre-commit hook, and the commit succeeds.
- [ ] A commit containing a staged file with a real oxlint `error`-severity violation is
      rejected by the pre-commit hook (non-zero exit, commit does not complete).
- [ ] `pnpm format` runs Prettier across the repo (respecting `.prettierignore`) and
      exits 0.
- [ ] `.oxlintrc.json`, `.prettierrc.json`, `.prettierignore`, and `.husky/pre-commit` are
      committed to the repository.
- [ ] `package.json` contains `oxlint`, `prettier`, `husky`, `lint-staged` as
      `devDependencies`, and no `eslint` package is present.
- [ ] A fresh `git clone` + `pnpm install` produces a working pre-commit hook without any
      manual step beyond `pnpm install` (verifies the `prepare` script re-creates
      `core.hooksPath` wiring).
- [ ] Automated tests: **N/A this change** — there is no application logic to unit-test;
      verification is the lint/format commands plus the two manual hook checks above.
      `jest-expo` is a separate M1 issue and is not pulled forward here.

## Constraints

- **No ESLint.** Per the issue's explicit note, ESLint is not installed, even
  transitionally or alongside oxlint.
- **No type-aware oxlint rules.** oxlint supports a `typescript.typeAware` config option
  for rules that need real type information, but it requires wiring a `tsconfig.json`
  reference and is measurably slower. Not enabled here — a future issue can turn it on if
  a specific type-aware rule is wanted.
- **No CI wiring.** This issue installs local tooling and the git hook only. Whether
  `pnpm lint` / `pnpm format --check` also run in a CI pipeline is out of scope — there is
  no CI configuration in this repository today.
- **No `format:check` / `lint:fix` convenience scripts.** Only the two scripts the issue
  asks for (`pnpm lint`, `pnpm format`) are added, to keep `package.json` minimal; add more
  if a later workflow needs them.
- **Existing `src/` files are reformatted, not rewritten.** Step 7 runs Prettier across
  the current tree once to establish a clean baseline; it must not change any file's
  behavior, only its formatting.
- **Not addressed here:** `jest-expo`, `@testing-library/react-native`, and Maestro are
  separate M1 stack items (`CLAUDE.md` § Tech stack) and are not installed by this issue.
